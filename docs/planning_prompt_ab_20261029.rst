只改变任务规划提示词的对照（2026-10-29）
======================================

结论
----

本轮只比较 PLANNING_PROMPT，不比较参数提取提示词，也不修改业务代码。
在本次固定输入、重复测试范围内，两版任务数和 depends_on 依赖结构相同，
未复现销售公司问题重复展开成六任务。交付文字及部分 dependency_bindings 有差异，
因此不能说两个提示词输出完全一样，也不能把后续 SQL、去重或最终汇总问题直接归因于本次规划提示词变化。

实验范围
--------

* 对比 ``7d2dad3^`` 与 ``7d2dad3`` 的 PLANNING_PROMPT；与此前同步快照核对，
  当前规划提示词等于后一版本。仅有两段变化：总职责说明和任务边界规则11。
* 旧说明由参数提取生成实际计算绑定；新说明改为规划器在查询参数提取前完成计算方案，
  并补充多步公式、成分取数不得提前TopN、保留对象编码和共用分母范围等要求。
* CALCULATION_PLAN_PROMPT、参数提取提示词、任务展开代码、Schema 和模型调用代码均未改变。
  本轮没有调用参数提取、计算方案模型、ASL或SQL，不用下游波动评价规划提示词。
* 使用此前正常请求中真实记录的规划输入，固定补全问题、已识别意图、当前模型语义文件、
  通用规则、上轮任务表及输出Schema。每一对输入的动态上下文和user文本均按哈希核对一致。
  没有用重新运行意图识别或问题补全后可能变化的输入作比较。
* 20个历史问题中，19个进入此规划模型；其中一个包含两轮，合计20份规划输入。
  “当前语义模型中建立了哪些实体”走解释旁路，不强行送入规划器。
  每份输入两版各3次，共120次；品牌分组发现一次表述缺口后，两版各补3次，共126次。
* 模型qwen3.7-max，temperature=0，enable_thinking=false，有界并发3。
  输出再经过同一份 complete_boundaries，分别检查原始计划和成分展开后的计划。
* 全部126次返回可解析计划，依赖下标均合法，未输出extraction、SQL或是否去重等查询参数。
  20份输入各自的新旧任务数与 depends_on 图一致；这不是126次业务端到端通过。

重点问题
--------

1. 销售人员平均订单金额前五及所属销售公司

   两版各3次，原始计划都为“选前五、查公司”两个业务目标；同一展开逻辑均变成4任务：
   含税销售总额、订单笔数、计算平均金额取前五、查询入选人员所属公司。
   依赖均为 ``[[], [], [0,1], [2]]``，公司查询都绑定 ``业务员.销售员编码``。
   均保留2025年、前五、平均金额口径，没有把公司查询再次展开为平均金额公式。
   新版部分输出将笼统的“编码”写成“销售员编码”，但绑定身份没有变化。
   本次没有证据支持这两段提示词改动造成了六任务或重复查公司。

2. 华山医院、新华医院销售员及产品

   每题两版各3次，均为先选销售员、再查该销售员产品，后者依赖前者并绑定销售员编码。
   医院、时间、前置Top1及后续查询产品目标保留，没有把产品加入前置排名粒度。
   两版都使用“全部产品明细”一类措辞，而非旧版始终明确“产品名单”、新版才改成“明细”。
   这次只检查规划，未调用参数模型，因而不能给出去重通过率。
   去重参数仍属于参数提取职责，不能因本次比较而搬到规划器。

3. 上海市区域医院覆盖率

   两版各3次都为3任务，分子按各经销商，分母上海整体，最后计算覆盖率。
   两版都没有交付“上海整体单个覆盖率”的计划；语义文件将登记指标定义为经销商覆盖率，
   此业务口径与用户期待之间的偏差不是此次提示词改动后才出现。
   新版3次都明确要求保留经销商编码，旧版1次明确要求。
   原始模型输出新版3次都写“不再查询数据库”，旧版3次未写，但相同展开代码都会补齐，
   所以不能把原始措辞差异直接当作后续一定多查一次数据库。
   另一个需要注意的计划合同问题：纯计算任务的 dependency_bindings 按提示词应为[]，
   新版3次、旧版1次却给该计算任务填写经销商名单绑定。结构解析接受了它，
   不能据此声称业务合同完全正确；本次未测试其执行影响。

4. 上海前三家经销商的产品追问

   固定同一份已补全问题和上一轮任务表，两版各3次都只生成1个新增产品查询任务，
   保留三家公司名单、2025年10月及上海地区医院范围，没有重查上一轮排名。
   但两版各1次把交付从“产品明细列表”扩展为“产品及对应销售金额”。
   这是两版都存在的交付描述波动，不能认定新版独有，也不能未经业务判断就认定所有带金额的计划必错。
   新版有2次加“复用上一轮查询结果”前缀，但该任务仍描述新产品查询，未增加只复述历史结果的空任务。

5. 两个品牌在二级医院的销售额

   对“统计美敦力、波士顿科学在二级医院的销售额”累计每版6次：
   旧版6次都明确按品牌分组/各自金额；新版5次明确，1次只说两个品牌的含税销售总额，
   question和expected_output均没有“分组/各自”的区别表达。
   补测3次新版均恢复明确分组，属于本次样本中出现的偶发表述缺口，不能外推为稳定故障率。
   若业务目标是分别看两个品牌，该次计划表达不够清楚；本轮未验证后续是否实际合并金额。
   另一个带“两个品牌”的原问题，以及明确“按品牌分组展示厂家”的原问题，两版均保留分组交付。

6. 骨科、上海销售额阈值、三级医院数等

   骨科问题两版都保留骨科范围，无按科室比较任务；上海经销商阈值问题两版都保留
   上海、各经销商、大于100万，未漏分组业务含义。三级医院数均要求按三级筛选数医院，
   没有规划销售订单统计。费森尤斯问题两版均保留品牌、上海、最近一年，
   但都没有明确上海属于医院还是经销商，这个语义空白两版共有。

7. 上药公司明细

   两版都可能提前在交付物中写“国药公司名称、编码”等属性：旧版2/3次，新版3/3次。
   用户原问题只给公司名称和“明细数据”，规划已经可能引导后续实体选择。
   本轮只能确认这一计划表述，不在未查目录身份和实际执行的情况下断言其归属必然正确或错误。
