# 回答证据约束与五分钟总时限

## 目标与根因

Current Stage：按用户当前明确要求修复 V1 回答单位、无依据推断和并发排队时限。本轮不改变 V2 路由与替代门禁。

- PROVEN：修改前正式进程的 `request_timeout_seconds=120`，不是 140 秒。报告生成另设 60 秒预算，Agent 的 ASL 调用为 90 秒；Oagnet API 的请求预算为 85 秒，其单并发队列实际最多等待约 40 秒。多任务与并发请求共享队列，120 秒总预算可能在报告阶段结束前耗尽。
- PROVEN：Oagnet 容量不足返回 HTTP 429 和 `Retry-After`，Agent 原 HTTP 重试忽略该响应头，通常仅等待 0.2/0.4 秒。它会在服务尚未释放容量时立即重复请求。
- PROVEN：报告已有事实约束提示，但缺少明确的已执行分母与单位合同；模型仍曾把按订单笔数计算的金额写为“每单位”。
- PROVEN：提示词与有限关键词检查不能覆盖改写后的推断。真实复测还出现“排名逆转可能性低”、根据笔数判断稳定性、把负聚合金额解释成退货/冲销等无充分证据的表述。不能仅以数值表正确宣布全文通过。
- PROVEN：本次样本的时间覆盖不足有上游 `PARTIAL_AFTER_SOURCE_WATERMARK` 及已验证水位证据。这一局限应保留；它不能支持缺失影响轻微、排名可靠或缺失天数的猜测。

## 修改范围

1. 总处理时限默认 300 秒；ASL 客户端预算 180 秒，Oagnet 请求预算 175 秒，仍保持一个实际执行槽位。按当前模型超时配置，队列可等待约 85 秒。修改的是处理上限，提前完成仍提前返回。
2. HTTP 重试遵守合法 `Retry-After` 秒数或日期，同时共享一次调用的总预算，不按重试次数重新延长。鉴权、语义合同错误及禁止重试的 SQL 执行保持原有边界。
3. 报告读取实际计算操作的分子、分母，并结合当前模型语义说明中对应指标的登记单位生成表达合同。SQL 直接返回的指标也读取当前登记单位，不猜计算公式。只影响解释，不修改字段绑定、计算、ASL、SQL 或数据。
4. 对已复现的单位和推断错误最多纠正一次；对涉及原因、稳定性、缺失影响等句子，再基于本轮完整执行证据核对并分类。实际除法报告核对全部正文及摘要句子，避免同义改写绕过触发词。模型的 `supported=true` 不是新增业务证据：无已确认原因证据时，推断类句子不能发布；直接事实、定义、局限与核查建议仍须通过核对。核对器只能决定原句保留/删除，不能改数值、数据单元格、任务选择或新增结论。逐句处理保留同段中正确的数值说明。
5. 生成、纠正及结论核对共用原有 60 秒报告预算。核对不可用时保留表格和可用事实，去掉尚未证实的判断，不因报告措辞失败丢失已执行结果。正常数值比较、可复算运算与明确局限继续保留。

## 验证与发布

最终计数、全量前后差异、真实接口用例和发布结果以同目录 `verification.json` 为准。诊断只保留计数、状态、哈希与核对结论，不提交业务明细、环境内容、日志或签名链接。

- 使用前一轮相同源码的全量结果作为 Agent 基线：5,352 通过、232 历史失败。ASL 修改前基线：1,889 通过、32 历史失败。不得将历史失败当作全量通过。
- 针对原句 Top5、最低 Top3 并发执行，核对三个任务、完整输入、除法、排序、条数及七主节点顺序。中间试验中计算已正确但文字仍不合格的样本，仅记录为改进依据，不计为最终文字验收通过。
- 将预算从 90 秒改为 180 秒后，既有 HTTP 适配器测试中的默认时限断言同步更新。这属于用户新要求导致的旧断言过时（STALE_TEST），不是放宽业务正确性断言。
- 旧洞察提示测试要求任何情况下只能调用一次模型，与本轮增加依据核对的要求冲突（STALE_TEST）。测试现允许一次生成及一次核对，同时继续严格断言全部原有正确文字、数据、问题与输出协议不变；正常去重计数局限仍保留。
- 六个 ASL 请求的压缩时间排队测试完成，峰值执行并发仍为 1；另验证排队拒绝、超时不提前释放工作槽、服务端等待提示、总预算和禁止重试场景。
- 发布仅涉及六个运行文件。正式环境通过专用非敏感 systemd 预算覆盖项落实 300/180/175 秒，保留既有配置。发布前比较目标文件与候选源哈希、备份；仅重启 Agent 和 ASL，验证 Agent/ASL/SQL 健康及实际进程生效配置。

## 验收边界

五分钟是有限预算，不能保证任意并发量或外部服务长时间不可用时永不超时。真实复测覆盖普通双请求并发及原问题相近问法，不等同无限负载测试或所有自然语言的绝对无误保证。

并行修改的独立阻塞：测试期间正式服务增加了 `_collapse_analysis_computation_tasks`，会将含多个真实依赖的规划压成首个取数任务。实际原问题随后转成单查询，最低值表格的方向与文字不一致，并缺少最终输出节点。该文件本地已有其他工作线尚未发布的保护修改；本轮六个运行文件未覆盖它。隔离对照采用该变更前的规划快照验证报告与排队修复，不能将该对照冒充当前正式服务的整体验收。发布及最终验收状态详见 verification.json。

本轮未修改语义库、索引、授权范围或冻结的向量标准化规则。主节点保持“意图识别 → 任务拆分与规划 → 解析校验 → 调度执行 → 结果校验 → 数据洞察分析 → 最终输出”。历史报告中与本轮无关的规划、容量上限和遗留测试问题仍按原记录保留。

Cutover Blocker P0/P1、Catalog/Evaluation/Shadow Gap、V1 Replacement Readiness 不由此次 V1 修复消除。Next shortest blocking path：当前目标先完成真实回答与发布验收；V2 沿既有独立门禁推进。
