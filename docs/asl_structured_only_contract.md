# ASL 严格消费结构化参数

## 执行约定

结构化参数提取负责确定实体、指标、维度、展示字段、筛选、时间、排序、行数限制和去重要求。ASL 只把这些声明绑定到当前请求授权范围内的目录标准字段、标准值，并校验能否执行。

- 未提供结构化参数时停止，不再从原问题重新生成查询。
- 空数组表示没有该要求。ASL 不从契约、排序、历史问句或目录说明补指标、筛选、分组和展示列。
- 契约用于检查声明是否完整保留，不修补缺项。参数缺失、未绑定或不支持时返回具体问题。
- 空名单条件、无法匹配的展示字段、无法确认的筛选值不能被静默删除后继续查询。
- 排序引用的指标必须在结构化指标中声明。当前单字段排序协议不能静默忽略第二个排序字段。
- 依赖结果应在进入 ASL 前写入完整的结构化条件；ASL 不再从依赖契约补条件。
- Agent 收到 ASL 后不再补指标、改时间、补维度、删除排序或重新解释明细口径。重试不能自动填写条件归属。
- 授权范围和向量字段、条件值校验继续生效。技术连接、目录映射和明确时间文本的解析不增加业务要求。

## 两个独立字段

| 结构化参数 | ASL 字段 | 含义 |
| --- | --- | --- |
| 维度 | `dimensions` | 指定统计的分组粒度 |
| 展示字段 | `display_fields` | 指定需要返回的属性 |

明细的展示字段直接进入 `display_fields`，不会转成 `dimensions`。两个数组可以包含同一个字段；SQL 对相同表达式去重，不因重复角色生成两列或改变分组。

```json
{
  "dimensions": [{"name": "dealer.dealer_name"}],
  "display_fields": [{"name": "dealer.dealer_name", "alias": "经销商名称"}]
}
```

汇总结果中的额外展示属性仍须由已声明的分组唯一确定，或存在目录确认的多对一/一对一关联。SQL 可以把这些已证明不会拆分统计组的展示表达式加入 GROUP BY，以满足数据库语法；不会猜新的业务分组，也不会用 MIN/MAX 隐藏不唯一的对应关系。

例如，提取了销售总额和商品名称、经销商名称，却没有提取分组，拆开两个字段本身不能解决统计口径缺失。需要提取阶段根据原任务明确按商品、经销商统计；ASL 应说明缺少分组并停止。

前端展示保留独立的 `dimensions`、`display_fields`；SQL 工具输入说明也分别显示分组维度和展示字段。
