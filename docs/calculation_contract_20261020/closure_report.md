# 多任务计算执行合同修复

当前阶段：现有 V2_CONTEXT_V1_EXECUTION 路由下的 V1 计算交付修复；不开展 V2 切流。

## 根因与修改

PROVEN：计算任务已被调度，但共享入口没有消费“计算绑定”和“结果操作”，改用结果行数与少量关键词猜测运算。复合指标拆分还会丢失问题文本中的分组、公司展示及最终排名要求。完整合成输入下，原入口失败，底层确定性引擎可得到正确结果。

本次打通受控指令、前序任务及字段、完整数据集、运算和排序限制；保留已通过的兼容路径。公式只绑定当前说明文件登记的成分，不按依赖指标排列猜分子分母；旧说明只有依赖、没有公式时保留原计划及既有支持路径。内部排序的 order/limit 写法归一到数据集操作的 descending/count。

成分查询保留人员分组和关联展示；结构化查询形态只新增到计算输入路径。依赖下标在发布计划前转换为当前问题的任务 ID，查询去重同步保留计算引用。执行按响应的确切 dataset_id、当前模型及授权 Scope 读取，不取同会话后来的其他结果。不同列名的人员编码只依据已执行 SQL 的同一物理字段对齐，拒绝按姓名或行号拼接。

缺失、非有限值、零分母和不完整输入不伪造完成。计算结果保存为实际派生数据集，最终表格使用同一计算结果；质量提示继续传递。
