# 参数提取失败说明

校验确认缺失或错误后，直接说明哪一项没提取、提取有误或放错位置，不笼统地说“无法确认关系”。

| 校验事实 | 回复示例 |
| --- | --- |
| 筛选使用合作时长，指标列表为空 | 筛选条件用了“合作时长”，但系统没有提取出这个指标，所以无法继续筛选。 |
| 指标已提取，筛选值为空 | 系统识别了合作时长指标，但没提取出要比较的具体数值，所以无法按该条件查询。 |
| 指标被放到展示字段或维度，未作为指标提取 | 系统把“合作时长”放到了展示字段中，没有作为需要计算的指标提取，导致无法按它筛选。 |
| 筛选字段、比较方式或排序方向缺失 | 分别指出没提取出哪项字段、比较方式，或从高到低/从低到高的排序要求。 |
| 指标存在但绑定失败 | 指标已经提取，但没有正确匹配到当前可用的指标。 |
| 指标和数值存在，公式不能用于筛选 | 指标和筛选数字已经提取，但系统暂时无法按已登记公式完成筛选。 |

普通字段筛选不强制要求指标，数值零是有效条件值。同名字段也可能分别具有指标和普通属性含义，不能仅凭同名判断位置错误。目录不足以证明原因时保留不确定性，不把提取错误说成配置缺失。

## 实现和验证

- `Oagnet/structured_binding.py`：在组装可执行条件前检查字段、比较方式、值和位置；筛选所用的具体指标必须已选中，其他指标不能代替它。删除笼统的“运算符或值缺失”和“公式或阈值无法绑定”旧分支。
- `exception_explainer/prompt.py`：模型接收原校验原因和当前授权范围的语义参考，直接复述已确认的缺失项或错误位置。
- `exception_explainer/integration.py`：没有已完成结果的参数拦停只显示通俗解释；保留原状态、候选、恢复信息及已有结果和附件。
- 不自动补指标、分组或筛选值。2026-10-27 用户对服务器召回及最终复查的选择见 `asl_deployment_user_choices.md`；此前的严格筛选值和单域召回说明不再适用于本次确认保留的服务器行为。

独立版本工作树验证：Oagnet 专项 109 项通过；解释组件及 Critical Suite 51 项通过。新增参数诊断用例 24 项全部通过。Oagnet 扩大回归由 1961 通过、27 失败变为 1985 通过、27 失败；逐用例比较没有新增失败，原有失败未纳入本次修复。开发目录的既有失败数与隔离版本不同，不能混用总数。

真实模型隔离说明测试覆盖漏指标、漏值、错位、漏分组和公式不能用于筛选五种情况，均取得当前授权范围的语义文件；这不是原业务问题的端到端验收。
