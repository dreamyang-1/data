# 先规划任务、后提取参数：本轮收尾记录

日期：2026-10-20。基线：`7f642dbed55b0b8cf8bc47ae8757c531c16fcfdd`。本轮仅完善当前任务拆分与依赖执行，不推进 V2 切流。

## 根因与边界

- PROVEN：原模型提示和 Schema 把拆分、意图和参数提取放在一次输出中，并强调默认一个任务；后续 DETAIL 清洗会删除未在排序/条件中引用的登记指标，导致原有迟到的复合指标展开失去依据。
- PROVEN：实际隔离重放中还出现了仅列公式输入却遗漏最终计算、把依赖查询误标为本地计算，以及局部查询意图影响最终交付的问题。不能把这些不同阶段的缺陷全部归因于意图识别。
- UNKNOWN：历史失败那次完整模型原始输出不可得，无法逐字复原它第一次为何只输出一个任务。当前修复针对已复现的调用合同缺陷，不以截图推测替代运行证据。

## 最终流程

问题级意图展示保持原有行为。任务内部按以下顺序执行：纯任务规划 → 按登记口径补齐输入/计算依赖及交付物 → 一次批量提取任务参数（顺带返回子任务意图）→ 原有指标归一与清洗 → 原有 ASL、SQL、调度和回答链路。

规划阶段只记录任务目标、依赖、结果粒度和登记指标目标，不提前提取字段/条件 JSON。提取不能更改已规划的任务问题和依赖；按任务下标回填，缺失任务不能静默缩成单任务。已规划指标、粒度和最终分析要求不会被 DETAIL 标签抹掉。

复合指标可采用成分分别取数后计算，也可复用已规划的同粒度联合输入后计算；不以固定任务个数判断正确性。多指标保留全部交付物，不同粒度/有效样本口径不混用输入。分布样本保留登记的逐订单粒度，前置成分查询不会提前应用最终 Top N。

跨问题依赖指向前序问题展开后的最终输出。需要新字段/关系的依赖任务继续查库；本地任务必须有既有结果操作或可绑定的登记公式。子任务明确不返回指标时，不从前置排名描述中继承指标。计算按已执行 SQL 的身份字段对齐，单行订单样本不能误作全局标量广播；真正的单行全局分母仍受支持。

用户可见七阶段、总意图字段、Scope、Pending、多轮行为及 ASL/SQL 校验规则均保持原有合同。通过三方合并保留远端已有的多期趋势路由和时间排序；其他远端修改不在发布清单中。
