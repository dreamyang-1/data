# 基础问题及任务依赖执行检查

本轮只处理影响基础任务继续执行的已复现问题，不扩修历史测试、不改 ASL/SQL 及向量标准化规则。

PROVEN：真实请求“销售订单金额前3名经销商，再查询这些经销商的合作医院”存在三处断点。规划/计算结构错误发生在纠错范围之外，随后旧异常分支退回单次查询并显示完成；明细任务的实体粒度被重复补成不存在的展示字段，使已查回数据误报缺列；本地字段提取修复被指标名挡住，即使上游没有医院字段也未切换到新查询。

修复仅涉及 task_dag.py 与 orchestrator.py：计算输入在规划纠错阶段检查，最多重试一次；空可选结构按缺省处理；无效计划不再被吞为单查询；新关系字段确实不在前序数据中时移除本地操作并执行受控查询；保留实际明细展示字段，停止把实体粒度当作字段追加。规划失败也按七个既有节点如实显示跳过情况。

测试覆盖：单问题多任务、问题依赖展开后的末端任务、取前几名后向两个查询传名单、两个查询结果按编码而非行序对齐计算、独立问题并行、空结果/失败向下游传播而独立任务继续完成。使用完整的13行合成存档，取前2后两个查询均只接收所选编码；两份计算输入故意反序，最终结果分别为100和200。

离线全量：baseline {'passed': 5279, 'failed': 237}；final {'passed': 5291, 'failed': 236}；旧通过退化0，收集错误0；新增11项全部通过；Critical {'passed': 331}。历史失败保留，详见 test_delta.json，不宣称全仓全部通过。

真实接口逐条验证：依赖查询、后续计算、独立组合问题均完成，七阶段顺序正确。这里只保存任务关系、状态、耗时和验证元数据，不保存业务明细、凭据或下载链接。

已知限制：上海平均每单金额首次接口出现一次城市字段绑定追问；同口径订单笔数单查及整题复测随后完成。没有用取消筛选、改业务含义或放松向量标准化来强行通过；暂不能据此宣称目录字段绑定在任意模型输出下都无波动。该现象与已验证的依赖调度、完整名单及确定性计算分别记录。
