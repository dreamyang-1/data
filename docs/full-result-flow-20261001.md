# 完整查询结果与最终展示分离 — 2026-10-01

## 根因与边界

PROVEN：SQL 导出器对大结果只返回 20 行；Agent 导出失败兼容分支也截断
`data`；单任务与组合任务的洞察输入再次使用 `rows[:20]`。后续数据集计算
虽然保存完整结果，但调用方只继续传递其 preview。因此附件完整不代表分析完整。

PROVEN：远程名单清理已不生成技术说明，编排却用说明是否存在判断清理状态。
这会误用原始附件、丢失原始/处理后数据边界。已改用 NAME_LIST_CLEANUP 标记，
保留远程简化展示，不恢复冗余文案。

本次范围是恢复用户暂停的“完整处理结果用于校验、计算与分析；最终页面只显示
20 行并提供完整附件”。不是扩大 SQL 查询范围或取消用户 LIMIT/TopN。
上一轮 JOIN 安全检查、60 秒数据库执行超时、只读限制、Semantic Scope、
ASL 参数和节点顺序均不变；不修改配置、语义库、索引及 V1/V2 路由。

## 实现与文件清单

- `sql-translator/data_exporter.py`：完整 data 返回；超过 20 行导出同一份数据。
  导出失败保留完整数据，附件失败不能伪装成查询失败。
- `sql-translator/api_server_prod.py`：分析契约处理全量数据，变换后重新导出；
  不再挂旧数据附件。兼容真正的上游部分结果，不把预览长度写成完整总数。
- `app/adapters/http.py`：保留完整载荷，按实际行数与总数识别部分结果，
  不以有无附件推断数据完整性。
- `app/services/orchestrator.py`：单/多任务、依赖筛选和复用数据集保留全量；
  模型输入与展示独立。缓存材料补读必须核对当前会话和授权范围。
  清理/计算结果使用对应附件，未变化的完整 SQL 结果直接保存，不重复导入附件。
  清理状态改读结构化标记，附件不可用时明确说明而不丢弃完整分析数据。
- `app/analysis/synthesis.py`：澄清完整数据、最终页面预览与真实部分结果的边界，
  不改变原有分析风格。
- `app/presentation/root_report.py`：最终 Markdown 表格最多 20 行；不修改底层数据。

新增 `tests/test_full_result_flow.py` 和
`sql-translator/test_full_result_contract.py`。更新现有 export、split API、分析编排、
