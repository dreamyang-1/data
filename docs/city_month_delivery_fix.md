# 按城市和月份查询的分类与交付修复

## 原因与改动

PROVEN：GROUPED_AGGREGATE 已支持 TimeSpec，按月取数不要求 TIME_SERIES。
识别提示词此前未明确区分这两种交付物；补充正反例，由模型理解完整语义，
不增加“每月”关键词分类规则。同步更新 V1 意图提示词与 V2 两阶段提示词。

PROVEN：有分析结果时，最终答案跳过了查询结果表。现在有显式分组维度时，
附加经过校验的数据表；已有结构化排名表不重复附加。

PROVEN：缺少系列或系列不足以区分数据时，重复时间点可能连成错误轨迹。
图表构建阶段现在检查时间/系列组合唯一性，不能证明时不输出单折线。

## 验证

- 分析展示相关 36 项通过；关键多轮及语义合同 33 项通过。
- 原问题真实 SSE 链路：METRIC_QUERY，31 行城市/月份/销售额表，约 88 秒。
- 显式趋势对照：保留趋势分析及 31 行城市月份表，约 77 秒。
- 两次均经过真实 ASL、SQL 翻译和 SQL 执行。未提交原始业务数据或运行日志。
- 全量回归：4034 passed / 4 failed，无收集错误。其中一个新增失败是 prompt_version
  类型未接受 v11，已保留 v10 兼容并接受 v11；修复后相关 40 项通过。
  其余三个失败为已有 memory/session-event/trace-summary 生命周期问题，归 A 返修。
  修复版本字段后未重复整轮全量，未将三项既有失败报告为通过。

## 剩余问题

- 城市列由上游返回编码，需审计发布维度的名称展示属性及关联映射，不能硬编码转换。
- 数据仅返回部分月份，不据此补零或声称全年数据完整。
- 模型及服务耗时仍偏高；本改动不宣称性能优化完成。
- A 正在修改 orchestrator 的事件生命周期，验收需按 diff 合入保留本次展示改动。
