# 查询诊断日志

查询链路增加 `query_diagnostic` 事件。数据智能体日志的方括号内是原消息 trace ID；事件中另包含请求 ID、任务 ID、语义模型和业务域。可按消息 trace ID 过滤 `logs/agent.log`，再按 `query_diagnostic` 查看同一请求的记录。

事件依次记录结构化参数槽位、ASL 的主体/指标/维度/展示字段/筛选字段/汇总筛选及拦停原因、SQL 是否包含分组/汇总筛选/连接以及 SQL 指纹、SQL 执行开始和结果行数或失败码。普通路径、快速路径及结构化参数拦停均覆盖；已有业务流程与前端节点不变。

筛选条件的值字段只记录类型、是否为空和指纹，不记录 SQL 明文或结果行；日期边界在符合日期格式时保留，错误原因中的内嵌参数对象及引号内容省略。目录名称和错误文本仍可能包含业务信息，应限制日志访问。指纹不是加密或脱敏数据库；需要核对某个值时应使用受控的原始请求记录。结构化参数的每类槽位最多记录 50 项，超过会标明省略数量。SQL 结构由文本摘要提取，是诊断辅助而非完整语法分析。

隔离环境用“统计上海市的含税销售总额大于100万的经销商”验证：日志中结构化参数的维度为空，ASL 维度为空，SQL 摘要显示没有 GROUP BY、存在 HAVING，执行返回 1 行；不依赖再次执行即可发现分组遗漏。该查询错误本身不在本次日志修改范围，不能把执行完成视为结果正确。

验证：日志、普通及快速路径、结构化拦停等专项 24 项通过；扩大范围测试 158 项通过、9 项失败，基线 155 项通过、同样 9 项失败，没有新增失败。真实问题历史回归另行记录。

日志可帮助定位已记录阶段，并不能保证服务进程在产生日志前崩溃、外部服务未返回细节或日志被清理时仍能确定根因；旧请求不会追溯补写。日志保留时间由现有服务输出和运维策略决定。
