# 维度与筛选条件判定契约

## 1. 目的

本契约用于统一意图识别、规范请求、ASL 规划、SQL 生成和意图展示中的结果粒度。`dimensions` 表示结果实际需要展开的粒度，`filters` 表示查询范围，二者禁止因“文本中都出现过”而混写。

## 2. 核心定义

- 维度：用于分组、比较或逐值展示的语义属性，会改变结果粒度。典型信号为“按……统计/分组/汇总/拆分”“各个、每个、分别、各自、逐个”。
- 筛选条件：用于限制数据范围，通常进入 `WHERE`，本身不要求成为结果列或 `GROUP BY`。
- 查询对象：用户希望返回的业务对象类型，例如经销商、商品、医院。查询对象不等于具体实体值。
- 实体值：上海市、TDC-3、费森尤斯等具体值；经过语义库规范化后进入相应筛选槽。
- 查询字段：明细或名单需要投影的属性，例如经销商名称、医院地址。字段投影不自动等同于聚合维度。

## 3. 判定顺序

1. 先识别任务意图和最终交付物：汇总指标、趋势、比较，或名单/明细。
2. 再识别查询对象、指标、返回字段、时间范围和具体实体值。
3. 将具体实体值及范围、否定、大小比较条件写入 `filters`。
4. 仅将明确要求逐值展开的语义属性写入 `dimensions`。
5. 对同一语义属性使用规范属性 ID/编码或语义角色族比对；只有同时存在筛选证据和展开证据时，允许同时出现在两组中。
6. ASL 和 SQL 必须分别校验筛选无损传递与分组粒度完整性，禁止把筛选字段自动补入 `GROUP BY`。

## 4. 具体规则

### 4.1 实体与名单

- “查询 TDC-3 的经销商名单”：TDC-3 是规格型号筛选；经销商是查询对象；经销商名称是返回字段。若无统计指标，不因“名单”自动制造聚合维度。
- “统计各经销商销售额”：经销商是维度，销售额是指标。
- “查询上海市各经销商销售额”：上海市是城市筛选，经销商是维度。

### 4.2 同字段双重角色

- “只看上海市，按城市统计销售额”：城市同时进入筛选和维度。
- “上海市销售额”：上海市只进入筛选，不加入城市维度。
- 条件操作符本身不能阻止显式分组；“排除上海市，按城市统计”仍是城市筛选加城市维度。

### 4.3 时间

- “最近30天”“2025-01-01至2025-12-31”写入专用时间范围，不作为普通维度。
- “按月/季度/年统计”形成时间粒度；时间范围与时间粒度可同时存在。
- 不允许把系统默认时间范围误称为用户筛选值，展示时必须标注来源。

### 4.4 多值、范围和否定

- “只看上海和江苏”是多值筛选。
- “分别比较上海和江苏”是多值筛选加比较维度。
- 大于、小于、不等于、排除等表达只提供筛选证据；若另有明确分组表达，同一字段仍可兼任维度。

### 4.5 空值

- 缺失或空的筛选值直接丢弃，不能生成 `field = ''`。
- 用户明确要求“为空、未填写、缺失”时保留 `IS NULL`/空值业务语义。
- 维度空值在投影和分组阶段映射为统一展示桶，不反向生成筛选条件，也不修改主数据原值。
- 当前已登记的医院等级空值标签为“未填写”；若要全局改成“未知”，应作为独立展示口径迁移并同步更新语义定义与回归基线，不与本次角色分离混改。

## 5. 模糊场景

不得将模糊字段强行放入筛选，因为没有筛选值时无法生成有效条件。先保留已确定槽位；只有不同解释会实质改变返回粒度且无法从上下文唯一恢复时才追问。追问应明确说明待确认的是“限定范围”还是“分别展示”，不得要求用户重复已给出的实体、指标或时间。

## 6. 可审计输出

不展示模型内部推理过程。展示层为每个规范化槽位提供可核验事实：规范名称、来源、角色和触发表达。例如：

- 维度：经销商（依据：“各经销商”要求逐行展开；来源：当前语义模型向量库）
- 筛选：业务城市 = 上海市（依据：“上海市”限定范围；来源：用户输入，经向量库规范化）

执行层始终以规范请求中的 `dimensions[]`、`filters[]` 为准，展示快照不得反向修改 ASL、SQL 或会话状态。
