## 已证实的问题与修复

- **PROVEN**：活动模型登记地址为空，但现有同步服务已生成真实说明文件。现在按原生产者协议读取同模型真实文件，完整进入规划和洞察上下文。真实文件及模型读取内容 SHA 一致，9435字符；没有合成目录冒充说明文件。
- **PROVEN**：完整问题生成器仍在，入口却仅消费有限提取参数。恢复原 PromptBuilder 和原提示规则优先生成，结构化参数作为参考；保留目录、授权和只读边界。已选标量指标的数值 HAVING 使用其输出别名，解决 MySQL 1054，未放开任意 SQL。
- **PROVEN**：前序结果指代被当成名称，“这家／他们”等句式未稳定绑定。现按真实 DAG 边传递同 Scope 的完整编码集合；SQL 前证明约束仍存在，保留用户字面筛选与排除条件，不改写原始事实。前置 Top N 不变成“对象和产品组合”的 Top N。
- **PROVEN**：依赖任务的明确年份与旧全历史标记冲突；只在已解析的 DAG 子任务清除冲突标记。已有表里缺少新字段时，规划器不能把新关系查询冒充本地投影；用户明确不查库仍受保护。
- **PROVEN**：远端新增复合指标展开后，部分依赖仍指向旧下标，原复合参数又被带给成分查询。已保留远端功能并修正输入、输出依赖映射、逐任务参数和查询／计算标记。
- **PROVEN**：模型补入目录默认“最近12个月”，规划却把12判成自造数字。现在只认可当前说明文件登记的默认时间，完整任务继续携带该时间；用户明确年份和未登记的默认值仍受原校验约束。
- **PROVEN**：共同分母被误拆为按经销商或经销商所在地区分组，还被附加交易日期，SQL把日期落在 hospital.id 上，造成零分母。按现有 `[dealer_shared_region_denominator:v1]` 目录合同修正成分任务：分子保留订单时间，分母使用区域医院主数据全量口径并保留区域筛选。没有该标记、用户明确按城市分别计算或其他指标时不套用这项修复。
- **PROVEN**：保留远端允许结构化参数承载年份、排名、指标的规划改动，修正其新增的短语集合与字符集合误比较，避免“只看／排除”问题误拦截。
- **PROVEN**：月度取数后洞察读取不存在的 delta；改读实际 absolute_change，消除查询成功后输出阶段失败。
