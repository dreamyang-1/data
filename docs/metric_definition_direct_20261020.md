# 解释口径直接回答（2026-10-20）

本轮按用户明确要求，将纯口径解释作为固定七节点的例外：保留“意图识别 → 任务拆分与规划 → 最终输出”，识别为解释口径后，在当前授权范围检索向量库登记说明并直接回答，不再生成解析校验、调度执行、结果校验和数据洞察分析节点。普通查询、计算及混合请求中的数据任务继续执行原有流程。

## 已证实的原因与修改

- PROVEN：原问题“订单笔数的统计口径是什么？”被执行为METRIC_QUERY，产生ASL、SQL和洞察，答成实际数值查询。规划提示把解释过度限定为“未登记且不可派生的概念”；复合指标说明也有被展开成取数、计算的风险。
- 规划用`definition_only`声明说明交付，参数阶段保留解释意图，禁止将其变为业务取数或复合指标计算。修正相互矛盾的提示，不新增独立意图模型调用。数据查询与口径解释的组合请求分别保留各自任务。
- Oagnet新增只读`/vector/metric-definitions/lookup`，直接读取当前模型及授权业务域内的指标向量记录。名称、编码或已登记同义词唯一匹配后返回说明；未找到、存在冲突或说明未登记时如实告知，不借用相似指标或其他模型/域。向量检索不生成ASL、不刷新索引、不查询业务数据。
- Agent解释路径直接展示登记口径、单位、适用范围等。用户询问公式时展示已有登记公式，不执行公式。该路径不再进入取数补全、结果数据集复用、结果校验或洞察模型。
- 多个解释任务逐项交付；说明性依赖不被误当成数据集计算。混合任务中解释子任务只完成自身状态，不产生虚假的查询节点，也不会阻塞真实查询任务的展示顺序。
- 原ASL、SQL、向量业务值校验规则未降低。SQL服务无代码修改，语义库及索引无写入。
