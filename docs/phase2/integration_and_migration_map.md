# 集成点与迁移地图

## 原则

不采用大爆炸式重构。以版本化契约、shadow、双写/双读、指标门禁和可回滚适配器逐阶段推进。

## 阶段依赖

### 阶段0：证据与目录治理基线

完成目录版本、自然键、指标代数最小字段、关系基数审查和完整Trace字段定义。它必须最先完成，因为没有稳定ID/版本，后续计划差异无法解释。验收：目录快照可复现、发布状态可追踪、30条失败能保存完整阶段输入输出。回滚：只停用新增元数据字段和Trace采集，不影响旧查询。

### 阶段1：多轴解析与Slot Reducer shadow

DataAnalysis并行生成多轴结构和任务版本，不改变旧执行。验收：200种子与新增多轮金标达到门槛，REFRESH/REVISE/ADD/REPLACE/REMOVE互不混淆。回滚：关闭shadow特性开关。

### 阶段2：角色优先语义解析与Typed Plan shadow

Oagnet返回mention span、角色化N-best候选、规范ID和拒绝原因；同时生成Typed Plan并适配为ASL 1.0。依赖阶段0目录稳定ID和阶段1角色请求。验收：候选召回与Top1、计划等价率达标。回滚：继续使用旧ASL生成。

### 阶段3：ASL/SQL契约扩展与ResultContract

SQL Translator接收版本化计划或ASL v2，增加比较、grain安全、通用结果证明和受控修复。依赖阶段2 plan稳定。验收：双译SQL语义等价、1:N不放大、结果契约覆盖列/粒度/顺序/数量。回滚：按版本路由ASL 1.0。

### 阶段4：灰度切流与旧路径退役

按业务域和查询形态灰度，持续比较业务结果。只有质量、延迟、成本和隔离门禁稳定后才退役旧派生逻辑。回滚：域级路由恢复旧版本。

跨仓库责任见 `cross_repository_change_matrix.csv`。
