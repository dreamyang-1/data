# ASL 向量标准值强制门禁修复（2026-10-20）

结论：PROVEN。原问题“上海的经销商有哪些”在线上模型 130 返回合法字段 `dim_province.province_name`，却携带原词“上海”，并标记 `asl_validation=PASS`。同模型的实际向量记录明确发布了“上海市”，不是缺少该标准值。

## 根因与修复

1. 当前 `main → _recover_question_asl` 主路径恢复了完整问题生成 ASL，却未调用备用结构化绑定路径的标准值绑定。`_validate_vector_grounded_asl` 原本仅验证字段、实体、指标等目录成员资格，不验证业务筛选值。因此正确字段能掩盖未标准化的值。
2. 整句的有限向量召回会被大量包含“上海”的医院名称挤占，省市标准值不一定进入候选池。实际值记录使用 `source_table=dim_province, source_field=province_name`；只按 `source_field=dim_province.province_name` 过滤会漏掉这些已发布记录。
3. 最终 ASL 现统一执行字段与值门禁，覆盖主生成、备用绑定、契约补全后的条件以及关联目标条件。缺少标准值时，按已经绑定的具体字段，在当前模型/业务域内补查向量，同时兼容上述两种存储格式。相似度只用于召回；只接受同字段、唯一、可证明等价的标准值，不按相似度强选、不硬编码上海的业务标准。
4. 已生成标准值时，仍为调用方原词保留同字段的向量凭据。使用现有 `ADD_SOURCE_RESOLVED_ENTITY_FILTER` 回执，兼容调用方条件完整性检查，无需修改请求或 SSE 格式。契约原始措辞保留，执行 ASL 使用标准值。
5. 数值阈值、日期边界、明确编码及运算符继续依照绑定字段的类型和现有合同处理。没有唯一值证据、跨字段/跨模型/跨域返回或依赖失败均不能标记通过。规则已加入工作区根目录、DataAnalysis_Agent 以及版本仓的 AGENTS.md，按用户要求永久冻结，后续修改不得降低。
