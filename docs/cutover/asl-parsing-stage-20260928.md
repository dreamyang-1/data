# 独立 ASL 解析校验节点

## 授权与范围

用户明确要求在调度执行之前新增“解析校验”，覆盖此前六节点展示约定。
正式顺序：意图识别 → 任务拆分与规划 → 解析校验 → 调度执行 → 结果校验 → 数据洞察分析 → 最终输出。
普通单任务最终答案仍使用现有输出区域，不借本次改动增加重复标题。

## PROVEN / 修复

- API 把 ASL_GENERATION 和 SQL 事件映射到同一 execution 展示区域，是 ASL 出现在调度执行里的原因。
- ASL_GENERATION 映射独立 parsing 区域；保留原 ASL JSON、字段解释和绑定提示，不改变 ASL/SQL 数据。
- SEMANTIC_QUERY_PLANNING 虽然名字包含 semantic，实际承载 SQL 翻译完成事件，保留在调度执行。
- 普通查询和 surface 入口在 ASL 调用前报告解析开始；语义重试与结构化追问也在解析节点报告。
- 多任务仅缓冲后续阶段的展示事件，等各任务跨过解析边界再展示 SQL，不串行化真实工具调用。
- ASL 追问任务仍参与既有结束屏障，但不伪造其 SQL 执行内容；正常兄弟任务可以完成输出。
- 保留已有 SSE stage 名称、think-tag 协议、授权、查询、缓存、Pending 和 SQL 服务行为。
