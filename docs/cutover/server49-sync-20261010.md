# Read-only server-to-local source synchronization

Current stage: source alignment only, not a feature repair or V2 release.

## Scope and safety

The deployed server is the authority for this pull. Source snapshots cover the
eight corresponding workspace projects: DataAnalysis_Agent, Oagnet,
sql-translator, dsl_md_service, formula_service, mcp-tools, ceshi and cs.
Every copied file is listed in a private manifest, checked before overwrite,
backed up and compared using SHA-256. Remote files are rechecked after download
and during a final drift refresh. No remote source, service, environment,
semantic database or vector index is modified or restarted.

805 source/support/license files match the server snapshot in the development
workspace. The canonical repository matches 804 of these files. The exception
is `tests/test_semantic_description.py`: the deployed test includes private
live-service URLs; it is preserved privately in development, not newly added
to the public repository. Two dependency license files are included alongside
their corresponding vendored sources.

Environment configuration, credentials, generated semantic descriptions,
operational records, caches, build products, temporary diagnostics and private
evaluation artifacts are excluded. Diagnostic scripts or documents with
embedded live credentials are quarantined, not copied into source/Git.
1,373 existing local-only/protected files are checked for non-modification.
Local regression tests and engineering documentation absent from the server
remain available; there are no local-only runtime implementation files in the
reviewed Agent/Oagnet/SQL paths. No directory mirroring or deletion is used.

## Verification and retained issues

- Python syntax: 602 files passed.
- Isolated offline Agent checks: baseline 228 passed / 1 skipped; final
  refreshed runtime snapshot 225 passed / 4 failed. Three failures require
  the full question to be repeated in the final report; table/chart section
  checks passed. One retained local native-router fixture no longer injects
  the single extraction through the updated server's planner path.
- Oagnet targeted: baseline and downloaded snapshot both 443 passed.
- SQL baseline: 174 passed. Bounded downloaded-snapshot checks: 126 passed and
  3 reported failures across the completed modules. The single-domain module
  also reports failures before stalling and is terminated after a bounded
  timeout; this module is not counted as verified or as zero failures.
- SQL retained mismatches include an obsolete 20-row interface assertion
  despite the existing full-result contract, and a SQLite fixture lacking
  `semantic_model_data_source`. These are test/source synchronization issues,
  not evidence that a live business database is missing this table.
- All validation runs use isolated copies without environment files, external
  network access or production/index writes. An initial stalled SQL test
  subprocess was stopped; only the isolated test process was terminated.

Full regression is NOT claimed green. This pull deliberately preserves the
server version, including its incompatible assertions/fixtures, rather than
editing production code or tests to make synchronization appear successful.
Detailed baseline/candidate XML, bounded timeout logs, file manifest, backup
and source hashes are retained privately. No production readiness or V2
replacement decision is implied. The next separate task, if requested, is to
align the retained regression fixtures/expectations with the current contract.

The server changed concurrently during this pull. Updated planning/runtime
files and a subsequent bridge-test update were refreshed separately, with
both the original local files and intermediate snapshot retained. Equality
means the final verified snapshot, not automatic continuous synchronization
with future server edits.
