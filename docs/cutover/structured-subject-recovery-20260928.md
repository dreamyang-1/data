# 结构化明细查询主体绑定回退

## 现象与证据

用户问题：查询空心纤维血液透析器产品合作的经销商名单。结构化参数已有商品/经销商、经销商名称返回列和商品名称过滤，但 ASL 提示无法确定实体并追问。

- PROVEN：新 structured_binding.bind 在字段绑定前，仅接受模型的 subject 字符串；缺失、对象形状或非目录键直接加入实体歧义，阻断后续执行。
- PROVEN：旧的 _detail_projection_subject_candidate 能根据已绑定字段与当前召回目录的关系图确定唯一主体；结构化主入口没有调用它。
- PROVEN：真实授权目录能召回 dealer/product/sales_order、该商品名称标准值及关系。同一结构化请求在隔离复测中成功生成 ASL，因此不能断言目录缺失。
- UNKNOWN：用户 13:31 那一次模型 subject 原始返回未取得；不能把“空值”“对象形状”或其他不合法值中的某一种说成已确认事实。

## 最小修复

仅改 Oagnet/structured_binding.py、Oagnet/agent.py：

- 提示词明确多个涉及实体不等于业务歧义，展示字段是返回对象，过滤是记录范围；允许授权的关联实体作为执行主表，不添加新业务条件。
- 兼容字符串主体和普通 ASL 的 {entity: code} 形状，仍要求在本轮实体集合内。
- 主体缺失时先完成结构化字段绑定；只有所有槽位可执行、无指标且有返回列，才调用已有关系图主体绑定函数。
- 只接受目录中唯一可连接全部引用字段的主体；不按关键词写死 sales_order，不扩大授权。不覆盖已有合法主体，不改指标查询主体，也不掩盖真正未绑定的过滤条件。
- 目录仍不能确定关系时说明技术绑定问题和已绑定字段，不再笼统要求用户解释多个实体的含义。
- 不恢复原问题提取、不增加默认时间/指标/分组、不改 SQL Translator、语义配置或 DataAnalysis 页面。
