计算规划与查询参数提取的职责
================================

任务规划节点先确定业务任务、交付物和依赖，并按当前语义文件展开登记复合指标。
在最终任务下标确定后，仍在规划节点内部完成计算执行方案：运算方式、指标输入、
来源任务、输出字段、计算后的筛选与排名。普通查询没有这个额外模型调用。

实现入口为 app/planning/calculation_plan.py。计算器支持的运算说明放在这里，
与计算规划提示词一起使用。明确的登记公式在规划阶段绑定；多步计算使用既有
受控结果操作。运行时数据集 ID 不由模型生成，仍由调度器等待依赖完成后提供。

app/structured_extraction/prompts.py 只描述已规划查询任务的参数提取。
calculation_task_indices 中的任务无需提取参数，可以返回 null 或省略；查询任务
仍需完整提取。参数提取生成的计算绑定和结果操作不会进入执行链路，规划器的
计算结果通过确定性适配转换为现有执行接口，不能被参数提取的输出覆盖。

计算排序的接口为排序数组中的 field/order，以及独立的整数限制。例如降序前五
使用 order=desc、限制=5。规划模型若采用计算器 sort_limit 写法，适配器转换其
既定方向和人数，不重新推断业务要求。源数据的身份、授权及向量绑定规则不变。

本次删除了参数提取提示词中的计算合同，以及参数提取完成后再补齐、覆盖登记
计算公式的调用链。用户可见节点和执行器接口不变。
