# 基础运算调用链修复（2026-10-20）

## 根因与范围

PROVEN：原问题“查询2026年各部门开票应收金额，结果需要展示部门名称”的可信请求范围为模型133、空业务域列表（当前模型内 MODEL_WIDE）。当前目录登记公式为 `payment_amount - write_off_amount`，说明文件登记依赖却按“核销金额、付款金额”排列。原规划模型已正确产生 subtract，但计算绑定只允许 divide，导致计划被拒绝；原执行器同样只有除法。放宽规划校验本身不能解决执行问题。

只修改 Agent 的必要调用链：

- `app/planning/calculation_bindings.py`：加减乘除的操作数角色、局部任务引用及当前登记公式绑定；保留原 numerator/denominator 除法。
- `app/planning/task_dag.py`：提取参数声明四则运算，登记成分拆分和绑定使用同一角色合同。
- `app/planning/task_plan_stages.py`：同一范围、同一粒度的登记加减乘公式自动展开为一次共同取数、一次计算，避免拆成独立聚合后产生不同对象集合；原有除法拆分保留。
- `app/planning/compound_question.py`：任务去重同时重定向 left/right，保留原绑定对象。
- `app/services/calculation_execution.py`：执行四则运算，按编码对齐跨任务数据；同名指标分开保留，保持减法及除法方向；完整输入、质量和零除检查继续生效。
- `app/services/orchestrator.py`：仅在派生结果的 provenance 中保留已证实的列绑定，防止后续任务将单个分组误当成全局标量。

ASL/SQL 生成、向量字段和值标准化、权限范围、意图展示、现有分析与澄清功能未改动。旧比例除法的正分母与时间兼容行为保留。新基础左右操作数除法接受负数，零除仍失败；基础运算允许零值及负结果。多步运算使用现有任务依赖或结果流水线，不执行任意代码或表达式。
