状态问题的具体原因
------------------

PROVEN：16轮单任务的最终响应均为COMPLETED，但SSE最后一份task_table的执行状态仍为“待执行”，
没有“执行中→已完成”的状态更新。包含上海产品追问两轮、合作时长、品牌销售、三级医院计数等。

代码对应关系：

* ``app/services/orchestrator.py`` 在生成任务规划时，为单任务和多任务都初始化“待执行”任务表。
* 多任务进入 ``_handle_task_plan``，通过 ``_emit_task_status`` 和 ``report_terminal`` 更新状态。
* 普通单任务查询走另一条执行入口，没有同样的任务表状态收尾；
  ``_persist_conversation_task_table`` 将原任务表连同查询结果概要保存，没有根据本轮响应修正终态。
* ``app/api.py::_thinking_events`` 只是转发已提供的任务表，不能自行把“待执行”改为“已完成”。

因此它是任务状态同步遗漏，不是任务真的没有执行，也不是参数提取模型需要判断去重或依赖。
旧提示词实验中上海经销商首轮也仅有“待执行”表，证明至少该场景在本次重启之前已存在同一现象。
不能仅凭本轮测试将所有历史状态问题都追溯到某一提示词提交。
