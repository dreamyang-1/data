# 新旧数据结构对比文档

> 本文档对比 Oagnet 项目从旧表结构（`meta_*` 前缀）迁移到新表结构（`semantic_model_*` 前缀）后，`mysql_tool.py` 输出数据的差异。

## 一、数据库表对应关系

| 旧表                           | 新表                                        | 说明                               |
| ------------------------------ | ------------------------------------------- | ---------------------------------- |
| `meta_entity`                | `semantic_model_entity_type`              | 实体类型主表                       |
| `meta_entity_attr`           | `semantic_model_attribute_config`         | 实体属性配置                       |
| `meta_entity_relation`       | `semantic_model_relation_config`          | 实体关系配置                       |
| `meta_entity_bind_metric`    | `semantic_model_entity_bind_indicator`    | 实体绑定指标                       |
| `meta_entity_bind_dimension` | （无对应表）                                | 实体绑定维度（新库未建表）         |
| `meta_metric`                | `semantic_model_indicator`                | 指标表                             |
| `meta_dimension`             | `semantic_model_dimension`                | 维度表                             |
| -                              | `semantic_model_entity_sub_table_mapping` | 实体子表映射（新库新增，未被查询） |
| -                              | `semantic_model_enum`                     | 枚举值表（新库新增，未被查询）     |

---

## 二、Entity（实体）对比

### 旧数据结构

```json
{
  "entity_code": "ent_order",
  "entity_name": "订单",
  "entity_alias": ["订单信息"business_domain": "trade",
  "update_frequency": "daily",
  "primary_key": "order_id",
  "business_definition": {"description": "订单主表"},
  "attributes": [...],
  "physical_table_join": {
    "base_table": "order_info",
    "join_logic": "LEFT JOIN order_item ON ..."
  },
  "relations": [...],
  "bind_assets": {
    "bind_metrics": [...],
    "bind_dimensions": [{"dim_code": "...", "dim_name": "..."}]
  }
}
```

### 新数据结构

```json
{
  "entity_code": "ent_order",
  "entity_name": "订单",
  "entity_alias": [],
  "business_domain": 4,
  "update_frequency": null,
  "primary_key": null,
  "business_definition": {"description": ""},
  "attributes": [...],
  "relations": [],
  "bind_assets": {
    "bind_metrics": [],
    "bind_dimensions": []
  }
}
```

### 字段差异明细

| 字段路径                        | 旧数据                          | 新数据                                  | 缺失原因 / 数据源                                                                                               |
| ------------------------------- | ------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `entity_code`                 | 来自`meta_entity.entity_code` | 来自`semantic_model_entity_type.code` | 数据库部分记录`code` 为 NULL/空                                                                               |
| `entity_alias`                | JSON 数组                       | `[]`（恒为空）                        | 数据库`alias` 字段为空                                                                                        |
| `business_domain`             | 字符串业务域                    | 数字 ID（`business_domain_id`）       | 类型变化，需关联`semantic_model_business_domain` 表获取名称                                                   |
| `primary_key`                 | 有值                            | `null`（写死）                        | 可从`semantic_model_attribute_config.is_primary_key` 推导                                                     |
| `physical_table_join`         | `{base_table, join_logic}`    | **完全缺失**                      | `semantic_model_entity_type.main_table_name` + `semantic_model_entity_sub_table_mapping` 表可提供，但未查询 |
| `bind_assets.bind_dimensions` | `[{dim_code, dim_name}]`      | `[]`（写死）                          | 数据库**无对应表**，无法恢复                                                                              |

## 三、Attribute（属性）对比

### 旧数据结构

```json
{
  "attr_code": "order_id",
  "attr_name": "订单ID",
  "data_type": "varchar",
  "field_mapping": "order_info.order_id",
  "description": "订单唯一标识",
  "is_nullable": false,
  "enum_values": [{"value": "1", "label": "已支付"}]
}
```

### 新数据结构

```json
{
  "attr_code": null,
  "attr_name": "工作表名称",
  "data_type": null,
  "field_mapping": "sheet_name",
  "description": "",
  "is_nullable": true,
  "enum_values": []
}
```

### 字段差异明细

| 字段路径          | 旧数据                          | 新数据                                | 缺失原因 / 数据源                                                                |
| ----------------- | ------------------------------- | ------------------------------------- | -------------------------------------------------------------------------------- |
| `attr_code`     | 有值                            | `null`（部分记录）                  | 数据库`semantic_model_attribute_config.code` 部分为 NULL/空                    |
| `field_mapping` | 完整字段映射（`表名.字段名`） | 仅`mapping_column`（字段名）        | **缺少 `mapping_table` 拼接**，应组合为 `mapping_table.mapping_column` |
| `enum_values`   | `[{value, label}]`            | `[]`（写死）                        | 可通过`semantic_model_enum` 表（`field_id` 关联）查询，但未实现              |
| `is_nullable`   | 直接取`is_nullable`           | `not bool(is_required)`（反向逻辑） | 语义等价，但字段名不同                                                           |

## 七、影响 Prompt 生成的关键字段

以下字段在 `prompt_build.py` 中被使用，缺失会直接影响 AST 生成质量：

| 字段                                     | 用途                                   | 新数据状态       | 影响程度                                             |
| ---------------------------------------- | -------------------------------------- | ---------------- | ---------------------------------------------------- |
| `metric.source_dependency.bind_entity` | 推断`subject.entity` 主实体          | `[]` 空数组    | 🔴**严重**：无法推断查询主实体                 |
| `metric.time_caliber.time_anchor`      | 生成`time_context.anchor`            | `null`         | 🔴**严重**：时间锚点缺失，SQL 无法定位时间字段 |
| `metric.calculation_rule.calc_formula` | 计算公式                               | 部分为空字符串   | 🟡 中等：影响复杂指标计算                            |
| `attribute.field_mapping`              | 生成`filters[].field`（表名.字段名） | 仅字段名，缺表名 | 🟡 中等：过滤条件字段不完整                          |
| `entity.physical_table_join`           | 物理表关联逻辑                         | 完全缺失         | 🟡 中等：影响多表 JOIN 生成                          |

## 八、数据质量问题

1. **`semantic_model_entity_type.code` 部分为 NULL/空**（23 条中多条无 code）

   - 导致向量索引 ID 重复（已通过 `or uuid` 兜底修复）
2. **`semantic_model_attribute_config.code` 部分为空**（153 条中 13 条无 code）
3. **`semantic_model_relation_config.code` 部分为空**（10 条中 1 条无 code）
4. **`synonyms` / `application_scenes` 类型不一致**

   - 旧数据：JSON 数组
   - 新数据：逗号分隔字符串
   - 需在 `_row_to_metric_dict` 中统一为数组
5. **`global_filters` 字段名风格不一致**

   - 旧数据：下划线（`filter_type`, `condition`, `desc`）
   - 新数据：混合驼峰（`filterType`, `filterCondition`, `filterExplanation`）
   - `prompt_build.py` 的字段顺序模板使用旧字段名，需对齐
