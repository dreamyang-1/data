本次合同与根因
--------------

用户明确要求：不论确定的是哪个字段，都按该字段缩小值匹配范围。
字段尚未确定时的候选消歧保持原有行为；字段已经确定后，不再到其他
无关字段借值或因其他字段含有该值而换字段。此规则不针对上海或地域字段。

PROVEN：原链路先根据提取的文字标签缩小实体范围，但选出物理字段后，
仍沿用这个较宽的候选池。医院“业务省/业务市”等标签不精确匹配属性名时，
候选池同时包含省份和城市字典，两个字典都有“上海市”，导致值匹配失败。
同日旧版正常入口重现了“这三家每家主要销售什么产品？”在业务市值匹配处停止。

修复只涉及 structured_binding.py 和 binding_ownership.py：

* 完成字段选择后，以该字段与已发布的字典关系重新收窄目录。
* 保留原请求授权范围；仅取现有候选字段的交集，不扩模型、业务域或实体权限。
* 标准值匹配、模型 value_ids 检查、后续修正统一使用收窄后的范围。
* 全局 value_ids 编号保持稳定，其他字段的编号不能混入当前字段。
* 数值、日期和明确编码仍走原有合同；同一范围内真正多义时继续报告歧义。
* 不修改任务规划、参数提取、意图、查询粒度、SQL 翻译或语义目录。

STALE_TEST：三项旧断言要求已绑定字段跨属性/跨实体借用型号值，与用户本次
明确要求冲突。已改为保留已绑定字段，没有保留旧行为作为回退。

历史问题内容检查
----------------

接口终态为 18 轮 COMPLETED、1 轮 NEEDS_CLARIFICATION、0 轮传输异常。
终态不等于业务验收。按实际条件、SQL、输出和附件检查：

* shanghai_pharma_company_details：经销商名称匹配，返回对应唯一档案。

  日期差指标、超过 90 天条件及名称均执行；仍受既有 1000 条明细默认上限约束，
  回答注明截断，不能称为全部符合条件的经销商名单。

未解决项必须保留：

  分组和分子地域归属问题在修改前已存在。

  与修改前成功记录相比，首次差异就在进入 ASL 前的参数中；不能算业务通过。
* longest_cooperation：提取同时把“合作时长”放进指标和展示字段，后者被拦截。
  该请求没有筛选条件，未进入本次修改的值匹配分支。
* tier_three_hospital_count：仍被默认订单时间范围限制为有订单的医院，非全量医院档案计数。
