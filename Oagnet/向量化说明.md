## 每日业务表全量覆盖同步

### 动态表和字段约定

表名和字段不再写死在代码或环境变量中。数据端每次触发同步时，都必须在 JSON 请求体中明确传入源表、唯一键、向量字段和元数据字段。服务按本次请求读取源表，并按 `source_table` 隔离和覆盖该表自己的历史向量。

表名和字段名只能使用字母、数字和下划线，且不能以数字开头。主键必须非空、唯一且长期稳定；向量字段每行至少一个非空。

### 数据端调用后的执行逻辑

服务不会主动启动每日定时任务。数据端每天更新完成后调用同步接口，服务才执行：

```text
全量读取源表
→ 校验主键和向量文本
→ 计算全部Embedding
→ Upsert本次完整数据
→ 删除本次已不存在的历史向量
→ 保存成功状态
```

只有读取、校验和Embedding全部成功后才覆盖索引。源表为空或处理失败时保留旧索引，避免数据端异常导致向量被误清空。

同步接口使用进程内锁与MySQL advisory lock；即使服务部署多个Worker或多个实例，同一时刻也只允许一个实例执行该表的同步。

### 数据端触发和成功回执

数据端每日更新完表后主动调用：

```http
POST /vector/daily-table/sync
Content-Type: application/json
```

请求体示例：

```json
{
  "source_table": "semantic_entity_attribute_value",
  "id_field": "id",
  "text_fields": [
    "entity_name",
    "entity_description",
    "attribute_name",
    "attribute_description",
    "attribute_value"
  ],
  "metadata_fields": [
    "semantic_model_id",
    "business_domain_id",
    "attribute_code",
    "updated_at"
  ]
}
```

接口收到触发信号后立即返回 HTTP `202 Accepted`，不等待读取和向量化完成：

```json
{
  "accepted": true,
  "message": "已接收同步请求，正在后台读取表并执行向量化",
  "job_id": "2f49693c-e328-4b02-83b7-69286fd1fe2a",
  "status": "QUEUED",
  "source_table": "semantic_entity_attribute_value",
  "accepted_at": "2026-08-21T18:00:00+08:00"
}
```

`accepted=true` 只表示服务已经接收并排队该同步请求，不代表向量化成功。数据端使用返回的 `job_id` 查询最终结果：

```http
GET /vector/daily-table/jobs/{job_id}
```

任务状态为 `QUEUED`、`RUNNING`、`SUCCEEDED` 或 `FAILED`。只有 `SUCCEEDED` 才表示表读取、向量化和覆盖全部完成；失败响应的 `error` 会说明旧索引已保留。

总体状态查询：

```http
GET /vector/daily-table/status
```

触发接口返回202表示请求格式合法且任务已接收；422表示表名或字段名格式不合法；409表示已有任务排队或执行。后台读取、表或字段不存在、空表、数据校验和向量化错误不再改变已经返回的202，而是记录为任务 `FAILED`。生产环境应由网关为触发接口增加服务身份认证，不能直接暴露到公网。由于调用方可以指定数据库表，数据库账号仍必须坚持只读和最小权限，避免读取非业务范围数据。

当前任务状态保存在服务进程内。首版部署应使用单Worker；如果部署多Worker或多实例，应把任务状态迁移到Redis/MySQL，并由网关保证状态查询可以访问共享任务记录。

## 内网联调启动

Oagnet 默认监听 `0.0.0.0:8021`。正常情况下执行：

```powershell
cd E:\YouoAgent\Oagnet
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_lan.ps1
```

当前开发机的 Trae IDE 会占用通配地址的8021端口。如果不关闭Trae，可只绑定真实内网网卡：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\start_lan.ps1 `
  -BindAddress 192.168.1.27 `
  -Port 8021
```

首次开放Windows防火墙时，需要使用管理员PowerShell执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\open_firewall_8021.ps1
```

其他部门使用以下地址联调：

```text
Swagger: http://192.168.1.27:8021/docs
OpenAPI: http://192.168.1.27:8021/openapi.json
```

本机内网IP可能因DHCP发生变化，正式联调应由运维配置固定IP或内部DNS名称，不能长期把个人电脑IP写死在Java配置中。
# 实体属性值向量化接口

目标表：`semantic_model_entity_att`。

接口：

```http
POST /vector/entity-attributes/rebuild
Content-Type: application/json
```

```json
{
  "semantic_model_id": 5,
  "business_domain_id": 9
}
```

接口会校验业务域属于指定语义模型，只读取当前作用域下未删除的数据，按作用域
覆盖 `entity_attribute_value` 类型向量，不影响其他语义模型、业务域或其他向量类型。
新快照向量化成功后才删除旧快照中已经不存在的记录；源表为空、字段不完整或
Embedding失败时保留旧索引。

向量文本由以下字段构成：实体名称、实体描述、属性名称、属性编码、属性描述、
属性值。Metadata保留语义模型ID、业务域ID、源表主键和业务字段。

问题改写和ASL生成时，`PromptBuilder`会与实体、指标、维度一起检索该类型，
并严格使用相同的语义模型/业务域作用域。

> 注意：属性值必须是允许用于语义检索的低敏感业务值。客户、手机号、证件号、
> 订单号等隐私或高基数明细禁止进入向量库。
