异常解释组件
============

本目录独立维护“异常证据 → 模型解释 → 用户回复”。业务执行流程只调用
integration.py，不在任务规划、参数提取或 ASL 中分散实现异常解释。

文件职责
--------

* prompt.py：面向业务用户的中文提示词；证据不足必须说明不确定。
* diagnostics.py：同一请求的节点、有限日志、异常链；脱敏并限制长度。
* model.py：兼容 Chat Completions 的模型调用，只解释、不修复、不执行工具。
* integration.py：智能体唯一接入层，覆盖抛出异常及已返回的失败/部分失败。
* tests/：并发隔离、脱敏、模型故障、真实接口事件合同等测试。
* third_party/：借鉴的开源提示词原则、出处及许可证。

当前复用智能体已配置的 intent_model_* 模型连接，不增加服务器配置文件，
不改变意图识别或任何业务校验。模型关闭或解释失败时保留已有具体错误信息；
解释器不会递归调用自己，也不把失败标记为成功。模型调用采用现有连接超时，
没有增加整体回答时限。

模型只能解释捕获到的证据，不能保证自动找到所有根因。正常补充条件、无数据
和用户主动取消不调用模型。进程被强制结束、服务无法启动、客户端断网时，
进程内组件无法向已断开的页面发送回复。已有历史错误需显式重放证据；不会
读取全局日志并混入其他用户或会话的数据。

测试：在 DataAnalysis_Agent 目录运行
``python -m pytest exception_explainer/tests -q``。
