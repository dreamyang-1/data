异常解释组件
============

本目录独立维护“异常证据 → 模型解释 → 用户回复”。业务执行流程只调用
integration.py，不在任务规划、参数提取或 ASL 中分散实现异常解释。

文件职责
--------

* prompt.py：面向业务用户的中文提示词；证据不足必须说明不确定。
* diagnostics.py：同一请求的节点、有限日志、异常链及拦停参数；脱敏并限制长度。
* model.py：兼容 Chat Completions 的模型调用，只解释、不修复、不执行工具。
* integration.py：智能体唯一接入层，覆盖异常、失败/部分失败及结构化参数拦停。
* semantic_reference.py：读取当前平台注册的语义文件，按请求授权模型和业务域限制参考范围。
* tests/：并发隔离、脱敏、模型故障、真实接口事件合同等测试。
* third_party/：借鉴的开源提示词原则、出处及许可证。

当前复用智能体已配置的 intent_model_* 模型连接，不增加服务器配置文件，
不改变意图识别或任何业务校验。模型关闭或解释失败时保留已有具体错误信息；
解释器不会递归调用自己，也不把失败标记为成功。模型调用采用现有连接超时，
没有增加整体回答时限。

结构化校验进入追问或失败时，模型会收到具体缺失项、提取参数、绑定失败原因、
已完成任务和当前语义文件，用于区分用户缺少必要条件、上游参数未传递、
字段/值未能绑定、时间字段未绑定、展示字段与分组对象关系未确认等原因。
校验已确认漏提指标、漏提条件值、提取格式错误或位置错误时，直接说明具体名称和
原因。筛选引用某指标不等于该指标已经提取；已提取但无法匹配也不能说成漏提。
解释使用不懂技术的人也能理解的业务说法。没有已完成数据的结构化拦停，
最终回答只显示模型解释，不再附加旧的技术说明和参数 JSON；候选、Pending、
任务状态仍保留在原字段，已有成功结果和附件保持原样。
当前模型文件不可用时明确标注，不借用旧文件或其他模型文件；显式单域请求
仅使用目录中核对过名称的对应章节，无法确认边界时不提供整模型文档。
参考内容最多40000字符并标注截断；语义文件不是绑定成功或配置缺失的证据。

模型只能解释捕获到的证据，不能保证自动找到所有根因。一般的条件补充、无数据
和用户主动取消不调用模型；结构化参数导致的追问纳入解释。进程被强制结束、服务无法启动、客户端断网时，
进程内组件无法向已断开的页面发送回复。已有历史错误需显式重放证据；不会
读取全局日志并混入其他用户或会话的数据。

测试：在 DataAnalysis_Agent 目录运行
``python -m pytest exception_explainer/tests -q``。
