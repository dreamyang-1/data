# 聚合指标全局条件修复

2026-10-20，本轮原问题全链路审计中的 SQL Translator 子项。

PROVEN：登记的订单级均价依赖金额、数量指标；SELECT 已展开公式，但全局条件仍把 `sales_total_quantity > 0` 作为物理列放进 WHERE，导致未知列错误。仅替换为 SUM 仍会把聚合放在 WHERE，且逐行剔除负数会改变退货净额。

修复在当前模型的已选指标及其登记依赖中展开条件引用，聚合条件进入 HAVING，行条件继续进入 WHERE。保留既有 JOIN 汇集、include/exclude 语义、限定物理字段和字符串字面量。空条件直接返回，避免引入不必要的目录查询。未修改模型目录、数据库配置或查询权限。

验证：新增 9 项，覆盖净退货、零数量、标量/分组、混合行条件、排除条件、限定物理列、字符串、复合公式与 JOIN。离线全量由 702 passed / 15 failed 变为 711 passed / 15 failed，旧通过退化 0，收集错误 0。使用当前授权目录的隔离编译器完成原指标的实际只读查询，确认 HAVING 正确且不再出现语义指标名充当物理列。

此修复只负责 SQL 聚合条件。完整原问题还要求先选订单、汇总整单全部商品、逐单计算和分布分析，不能用一个全局加权均价替代。
